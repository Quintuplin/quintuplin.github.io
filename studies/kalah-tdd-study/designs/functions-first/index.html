How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

Family: Structure first. Idea: Test-drive pure functions. Cluster them into classes later. What it changes in the search: The map. Drawn after the code exists.

once:1. List the spec's verbs as a test backlog. Leave nouns for later.2. Model state as plain data records with no behaviour.3. Test-drive each verb as a pure function over that data.4. Keep input and output in one thin shell that calls the pure functions.5. Tabulate each function's callees and the record fields it reads or writes.6. Assign each function to the record it touches most. Else join its main caller.7. Split any cluster over the lint method cap. Move each into a noun-named class.8. Keep tests green. Regenerate the noun-verb map. Count cross-cluster calls. Lint.

Once means one agent runs the steps. Repeat per unit means one agent per unit until no unit is open. Throughout means the rule joins every prompt. For up to n starts means separate attempts with the best kept. The harness does means the harness runs the step without an agent. If names the event that starts a stage, and with adds a rule borrowed from another method. Steps are quoted from args.json with their numbers. Tag: verified.

Review scores

A blind reviewer agent scored src/ and test/ from 1, worst, to 5, best, so the scores are unchecked. Reasons are the reviewer's own words, verbatim. This review is superseded by the blind rating of three raters in rating.json, whose medians fill the comparison's principle columns.

Review scores, 11 rows and 4 columns

Alterability. Item: Change Case 1: sow seeds anti-clockwise. Score /5: 5.

Reason: Direction lives only in BoardDrawing.draw, where one flag mirrors both rows and swaps the outer cells. The rules take no direction, and a test pins that both directions give the same move.

Alterability. Item: Change Case 2: 7 houses with 5 seeds. Score /5: 4.

Reason: The 7-5 variant is one constructor call in Kalah.play. Board and the drawing size themselves from the array length, but the 6/4 and 7/5 literals sit inline in play() and are not named constants.

Code quality principles. Item: 1. Clear Presentation. Score /5: 4.

Reason: Classes and functions are short and laid out the same way, and play() reads as a simple loop. The circuit-index arithmetic in Board (pit - size - 1, house - 1 + step) is compact and takes some effort to follow.

Code quality principles. Item: 2. Explanatory Language. Score /5: 4.

Reason: Names such as sow, capture, lastPit, opposite and nextMover use the game's own words, and the javadoc explains why. Some names are vague or misleading, such as the generic 'pit' for a circuit index and 'ascending' in houses().

Code quality principles. Item: 3. Consistent Code. Score /5: 3.

Reason: Board mixes instance getters with static functions that take a Board. play() draws with the clockwise parameter while end() reads it from variant.isClockwise(), so the same fact comes from two sources.

Code quality principles. Item: 4. Used Content. Score /5: 2.

Reason: Phase.QUIT and Phase.OVER are never used, and phase never changes from PLAYING. The clockwise field in Variant only feeds one drawing call, so phase is dead state.

Code quality principles. Item: 5. Simple Constructs. Score /5: 4.

Reason: Plain loops, an immutable copy-on-write board and a modular circuit index keep the code simple. Using one shared TIE/QUIT value of -1 and the immutable copying add a little ceremony.

Code quality principles. Item: 6. Minimal Duplication. Score /5: 4.

Reason: There is little repetition. The houses[player][house - 1] indexing appears in several places, and the 'lift seeds' count is read in both sow and lastPit.

Code quality principles. Item: 7. Modular Structure. Score /5: 4.

Reason: The split is clean: Board holds the rules, GameState sequences a turn, BoardDrawing renders and Kalah handles input and output. Kalah also holds the winner and score logic, which belongs with the rules, and the unused Phase dilutes GameState.

Code quality principles. Item: 8. Problem Alignment. Score /5: 4.

Reason: The code models houses, stores, sowing, capture and extra turns directly, and the board ends the game when the mover has no seeds. Treating direction purely as a drawing mirror fits the problem but is stated only in a comment.

Test quality. Item: Test quality. Score /5: 4.

Reason: Focused, independent tests with descriptive names cover sowing laps, capture edge cases, extra turns, game end, scoring, ties and drawing in both directions and both sizes. End-to-end coverage is one anti-clockwise 7-5 spec, and the clockwise and 6-4 full flows are left to the course suite.
