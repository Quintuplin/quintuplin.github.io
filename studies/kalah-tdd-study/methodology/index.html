How a design runs

Each design runs as a list of stages in harness/workflow/stages.json. A stage takes numbered steps of its method from tdd-methodologies.md, quoted through args.json. 18 stage sets hold 58 stages. recomputed

S: once
Once means one agent runs the steps. 32 stages.
L: repeat per unit
Repeat per unit means one agent per unit until no unit is open. 15 stages.
F: throughout
Throughout means the rule joins every prompt. 9 stages.
starts: for up to n starts
For up to n starts means separate attempts with the best kept. 1 stage.
H: the harness does
The harness does means the harness runs the step without an agent. 1 stage.

If names the event that starts a stage, and with adds a rule borrowed from another method. Steps are quoted from args.json with their numbers. verified

Rank the finished attempts by the score rule in SCORE.md, using the attempt results among the facts below. Pick the winner only among the finished starts. Held-out TDD s2
You are the separate agent. Return blocked if {cases} holds anything. Write at least 3 black-box cases per requirement as {cases}/<requirement>/<variant>/caseNN.txt, where <requirement> names a noun and <variant> is a variant folder name from examples/EXAMPLES.md, in the spec format of examples/specs. Keep generators and other scratch files in {scratch}, never in the clone, which the method agents read. Log counts only in LOG.md and commit LOG.md.
Held-out TDD s3
Run {split} {cases} {visible}, which keeps two thirds visible, and commit visible/. Log only the line it prints.
Held-out TDD L6-8
Drive with ./run.sh specs visible and ./run.sh test. Once the unit is green run ./run.sh hidden once and append a GAP.md row: time, label, requirement, visible pass/total, hidden pass/total and gap. Write a fresh visible test for each requirement ticked in UNITS.md that fails hidden. Write each fresh visible test under test/, never under visible/, which the harness re-splits. A spec file there goes in a variant folder, so ./run.sh specs test plays it. The harness does the rest of step 8 after this loop and replaces the hidden cases through separate agents, so leave the hidden set alone. Return in failing only the requirements ticked in UNITS.md that fail hidden, because the others are not built yet.
Held-out TDD s8-writer
You are the separate agent. Add fresh cases to {cases} for each requirement the facts below list as failing hidden, in the layout of {cases}. Keep generators and other scratch files in {scratch}, never in the clone, which the method agents read. Log counts only in LOG.md and commit LOG.md.
Held-out TDD s8-split
Run {split} {cases} {visible} again and commit visible/. Log the line it prints and the count of earlier cases it moved into visible/. Then run ./run.sh specs visible and ./run.sh hidden once and append a closing GAP.md row.

Prompts and the shared test list

The test-list order arms share one prompt and one test list. The methods doc states how the list is written. verified

One lister agent works once per run in its own clone and writes the list every arm shares.

  1. Number each functional rule in README.md and docs/SPEC.md as a clause R1 to Rn in CLAUSES.md. Leave out code quality and PMD rules.
  2. Rate each clause 1 to 3 for the chance a first implementation gets it wrong. Rate its usage 1 to 100 as the percent of moves in a typical game that exercise it. Rate a clause of one variant as the percent of games that use the variant times the share of their moves that exercise it.
  3. List at most 12 candidate tests in TESTLIST.md. Each names one behaviour.
  4. Give each candidate two fields. checks lists every clause its assertions observe, variants included. relies lists clauses it needs and does not assert.
  5. Estimate the production lines each candidate needs on the starter alone.
  6. Commit both files and return them as JSON.

The harness checks the JSON before any arm starts. Ids are unique, checks and relies name real clauses, there are 1 to 12 candidates, risk is 1 to 3, usage is 1 to 100 and each estimate is a whole number. A failed check stops the family. The harness divides each usage by the sum over all clauses, so the usage shares sum to 1.

The held-out split

Held-out TDD as the methods doc states it. Its design page covers its builds. verified

Visible tests drive the red-green loop. Hidden tests that the implementer never sees score milestones.

Mirrors: a train and validation split. The gap between visible and hidden pass rates measures overfitting.

  1. Pin the public interface first such as the CLI or the noun-verb verbs.
  2. A human or separate agent writes several black-box cases per requirement.
  3. Move about a third of each requirement's cases into a hidden set.
  4. Keep hidden tests in a private repo that only CI checks out. Keep its CI token out of the agent environment.
  5. Clone it outside the agent workspace. Add a permissions deny entry for that path in the assistant settings.
  6. Drive TDD and AI loops with the visible set alone.
  7. On each merge CI prints hidden pass counts per requirement. Log the gap.
  8. On a hidden failure write a fresh visible test. Replace that hidden case.

Pairs with noun-verb: pin the map's public verbs as the interface both sets test. The gap per noun shows where the code overfits.

Measure: visible and hidden pass rate per merge. Gap per noun. Hidden cases replaced after disclosure.

Fits when: an AI loop iterates hard against tests and a human or separate agent owns the hidden set.

Risk: each look at the hidden score leaks a little so the set ages with reuse. A solo author has seen the hidden tests so only the AI side is held out. CI logs that print assertions leak the set.

The separate agent writes the cases in stage s2 and stage s3 splits them. Their notes follow. verified

s2. You are the separate agent. Return blocked if {cases} holds anything. Write at least 3 black-box cases per requirement as {cases}/<requirement>/<variant>/caseNN.txt, where <requirement> names a noun and <variant> is a variant folder name from examples/EXAMPLES.md, in the spec format of examples/specs. Keep generators and other scratch files in {scratch}, never in the clone, which the method agents read. Log counts only in LOG.md and commit LOG.md.

s3. Run {split} {cases} {visible}, which keeps two thirds visible, and commit visible/. Log only the line it prints.
