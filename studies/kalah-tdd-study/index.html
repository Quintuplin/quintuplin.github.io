The study

Classic greedy TDD writes the smallest failing test and then the smallest change that passes it. Do TDD variants that plan the class structure first, change the step size, try several starts or change how the tests check the code lead an AI coding agent to a better Kalah solution?

The study has a survey and two contrast runs. A survey ran 11 methods once each in run full-1. Planned contrasts then ran 5 replicates each of four methods in run rep-1 and in run rep-2 of three new methods plus Classic greedy TDD, seven methods in all. Every build reached the functional ceiling of 15/15. In rep-1 Anchor Engineering scored a higher adjusted mutation score than Classic greedy TDD, all 5 replicates at 1.000 against a median of 0.984, with Holm p 0.016. Functions first, classes later and Noun-verb map did not differ, with Holm p 0.548. In rep-2 no survey leader differed from Classic greedy TDD on M, and Held-out TDD scored a lower adjusted mutation score with Holm p 0.024. recomputed

Key findings

All 11 methods score the functional mark 15/15, hidden 76/76, unseen 69/69 and acceptance 6/6. Only functions-first, mapped-path and noun-verb pass strict PMD compliance, as the reference does. The other 8 fail with 2 to 10 violations. The methods also differ in size, structure, mutation, cost, time, bench and rated code quality. recomputed

About the data

  • Awards rank the 11 survey builds of run full-1, one build per design.
  • Runs rep-1 and rep-2 made 40 repeat builds of 7 designs. Replicate medians and C come from them, and each design names its own runs and build counts.
  • Run tcp-1 is not ranked here. Five arms with one test-list order each for random, coverage, cost, risk and usage at seed 20261020.
  • Each run is its own batch, so costs from different runs do not compare.
  • The full research report is the full study report.

Terms

Functional mark
Marks out of 15 from the hidden course tests, scored as the A02 rubric does.
E
Errors: distinct PMD findings plus adjusted surviving mutants, those the hidden tests kill, plus failed hidden and unseen tests. Lower is better.
Cost to completion
Weighted tokens the agents spent to finish the build.
M
The mean weighted-token cost to pass one hidden test. Lower is better.
M_io
M with output tokens left out.
Alignment
The blind code-quality rating agrees with PMD on every principle and PMD finds no issue.
C
Consistency score over repeat builds of one design. Lower means steadier results. Exploratory.
PMD
A static analysis tool for Java. A finding is one rule broken in one place.
Weighted tokens
Model tokens weighted by price: input 1, cache write 1.25, cache read 0.05, output 5.
APFDc-H
How early the hidden tests pass: the area under the hidden pass curve over weighted tokens spent, divided by the cost to completion.
CQP
Code Quality Principles, the course's design principles. A CQP score sums the blind rating's medians over four of them, 4 to 20.
Adjusted mutation
The mutation score after dropping surviving mutants the hidden tests also miss, which are likely equivalent. Higher is better.
Planned contrast
A comparison of two designs fixed before the builds ran, tested over their repeat builds.
U
The exact two-sided Mann-Whitney statistic of a planned contrast: how many pairs of builds, one from each design, have this design's value above the other's, a tie counting half.
Holm
A correction that raises each contrast's p value, the chance of a gap this large with no real difference, so testing several contrasts at once keeps the false alarm rate at its usual level.

Designs

  1. Classic greedy TDD Smallest failing test then smallest passing change.
  2. Noun-verb map Plan classes from spec nouns and methods from verbs. Fill linked stubs.
  3. Mapped-path TDD Walk the map leaves first toward one acceptance test at a time.
  4. Functions first, classes later Test-drive pure functions. Cluster them into classes later.
  5. Transformation Priority Premise TDD Pick tests the simplest ranked transformation can pass.
  6. Coarse-to-fine TDD One big step per feature. Drop a gear when it stalls.
  7. Annealed refactoring Uphill refactors allowed early on a fixed cooling schedule.
  8. Multi-start TDD Independent attempts on one locked suite. Score rule fixed first.
  9. Most informative next test Write the test that rules out the most wrong implementations.
  10. Property-based TDD State rules over input regions. Generators sample and shrink.
  11. Held-out TDD Visible tests drive the loop. Hidden tests measure overfitting.
  12. Anchor Engineering Write claims that must hold with their checks. Build milestones behind a mutation gate and a judge.
  13. A02 reference (not part of the comparison) The A02 reference build by a human with AI, shown beside the designs and not compared with them.
