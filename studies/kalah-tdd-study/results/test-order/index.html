List phase steps

The lister of run tcp-1-list followed these steps.

  1. Number each functional rule in README.md and docs/SPEC.md as a clause R1 to Rn in CLAUSES.md. Leave out code quality and PMD rules.
  2. Rate each clause 1 to 3 for the chance a first implementation gets it wrong. Rate its usage 1 to 100 as the percent of moves in a typical game that exercise it. Rate a clause of one variant as the percent of games that use the variant times the share of their moves that exercise it.
  3. List at most 12 candidate tests in TESTLIST.md. Each names one behaviour.
  4. Give each candidate two fields. checks lists every clause its assertions observe, variants included. relies lists clauses it needs and does not assert.
  5. Estimate the production lines each candidate needs on the starter alone.
  6. Commit both files and return them as JSON.

Arm steps

Every arm followed these steps.

  1. Read CLAUSES.md and TESTLIST.md. Change neither.
  2. Build candidates in the order the harness gives. Log a new candidate in ADDED.md with its checks and relies.
  3. Write one failing test for the first open candidate and watch it fail.
  4. Pass it with the smallest change. Refactor on green. Commit each green.
