Structure first

Noun-verb map

Plan classes from spec nouns and methods from verbs. Fill linked stubs.

What it changes: The map. Fixed before any code.

No award in this survey.

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

once:Gather the spec and its acceptance tests. Write tests for any untested feature.Extract every noun and verb as Noun: -verb lists. Trim to the domain.Mark parents as Noun(Parent). Split nouns over 4 verbs. Apply Clean Code names.Replace duplicate verbs with references written as verb1(Noun2.verb3).Script-check for cycles, dangling references and nouns over 4 verbs. Fix each.Scaffold stubs that throw a TODO naming the referenced method. Fill one per prompt.Run the tests. Fix one failing test per prompt with the smallest change.Lint with no suppressions. Prune unused methods. Diff a regenerated map against the plan.

Structure first

Mapped-path TDD

Walk the map leaves first toward one acceptance test at a time.

What it changes: The map. Tests follow a planned route on it.

  • Silver Best overall rank sum 13.0
  • Gold Fewest errors E 2
  • Gold Best CQP/PMD alignment mean rating median 4.0

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

once:Build and check the map using steps 2 to 5 of noun-verb.also: Noun-verb map step 2. Extract every noun and verb as Noun: -verb lists. Trim to the domain.also: Noun-verb map step 3. Mark parents as Noun(Parent). Split nouns over 4 verbs. Apply Clean Code names.also: Noun-verb map step 4. Replace duplicate verbs with references written as verb1(Noun2.verb3).also: Noun-verb map step 5. Script-check for cycles, dangling references and nouns over 4 verbs. Fix each.once:Read each verb1(Noun2.verb3) reference as a call edge between verbs.repeat per feature until none is open:Write one failing end-to-end acceptance test for the next spec feature.List the verbs that test reaches. Order them leaves first.Per verb write the smallest failing unit test then the smallest passing change.Run all tests and lint after each verb. Refactor only while green.Add any verb the route lacks to the map first. Then re-route.Repeat from step 3 until every feature passes. Then diff the map.

Structure first

Functions first, classes later

Test-drive pure functions. Cluster them into classes later.

What it changes: The map. Drawn after the code exists.

  • Gold Best overall rank sum 11.0
  • Gold Most cost effective M 470,362, M_io 441,270
  • Bronze Fewest errors E 5

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

once:List the spec's verbs as a test backlog. Leave nouns for later.Model state as plain data records with no behaviour.Test-drive each verb as a pure function over that data.Keep input and output in one thin shell that calls the pure functions.Tabulate each function's callees and the record fields it reads or writes.Assign each function to the record it touches most. Else join its main caller.Split any cluster over the lint method cap. Move each into a noun-named class.Keep tests green. Regenerate the noun-verb map. Count cross-cluster calls. Lint.

Transformation Priority Premise TDD

Pick tests the simplest ranked transformation can pass.

What it changes: Move order. Cheapest transformation first.

No award in this survey.

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

once:Put Martin's ranked list with one-line definitions in the assistant prompt.repeat per feature until none is open:Pick the next test that the highest-ranked transformation can pass.Pass it with that one transformation. Name it in the commit message.Revert and try a simpler test if it needs while, function or assignment.Accept the lower-ranked move and log it if no simpler test exists.Refactor on green. Refactors change structure and never behaviour.Repeat until the test list is empty.

Step size

Coarse-to-fine TDD

One big step per feature. Drop a gear when it stalls.

What it changes: Step size. Large first then shrink on a stall.

No award in this survey.

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

throughout:Set four gears: feature, class, method, fake-it. Start in the feature gear.repeat per feature until none is open:Write one failing end-to-end acceptance test for the next feature.Attempt the whole feature in one assistant prompt against the acceptance test.Shrink rule: one failed attempt or 10 minutes red. Revert and drop a gear.In lower gears drive each class or method with its own unit test.Fake-it gear is classic TDD. Split any test still stuck there.Once acceptance passes add edge-case unit tests. Refactor on green.Return to the feature gear for the next feature.

Annealed refactoring

Uphill refactors allowed early on a fixed cooling schedule.

What it changes: Accepts worse designs early then cools.

  • Silver Fewest errors E 4

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

throughout:Hot may move nouns and verbs. Warm moves verbs. Cold renames and extracts.Timebox and allowed rise: hot 45 min 20%. Warm 15 min 5%. Cold 5 min 0%.repeat per feature until none is open:Run classic TDD. Log energy per commit: PMD warnings plus jdeps class edges.After each green try at most one allowed move on a throwaway branch.Pick the move after which the next test needs the fewest changed lines to pass.Merge if energy does not rise. Merge a rise within budget with a one-line reason.Revert any move still red or over budget when its timebox ends.Cool one phase per third of the original test list. Stay cold after.

What it changes: The check. Anchors and their criteria gate each milestone.

How it builds code

The steps the agent followed, in order. Indented lines run under the line above them.

throughout:Keep the Book current as the code changes. Log each decision and mark each milestone done.once:Write the Anchor Book ANCHORS.md at the clone root from README.md and docs/SPEC.md. It holds the design, each anchor as a claim that must hold about the system, the criterion that verifies it, and the planned chunks of work as milestones.Check each anchor against the others and the spec. Log each conflict and the decision taken in the Book.repeat per milestone until none is open:Per milestone, turn each of its anchors into tests that check it. Add tests for surviving mutants that break an anchor.Review the milestone as a judge for structure and correctness against its anchors. Fix what the review finds.
